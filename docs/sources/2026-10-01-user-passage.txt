可以。以 2026 年 10 月目前的狀況來看，**台灣買得到的 Xiaomi 智慧攝影機 C400，可以把 live 影像拉出來給你自己的程式使用**；只是它不是走「攝影機原生 RTSP/ONVIF + 官方公開 API」這條標準路線，而是要透過 Xiaomi 自己的加密 P2P 串流協定，再用中介層轉成 RTSP / WebRTC。

我查到台灣官網目前販售的 C400 型號是 **MJSXJ23CM**，解析度 2560×1440；台灣版使用手冊也明確寫出視訊編碼是 **H.265**。:chatgpt-content-reference{index="0"}

最重要的結論可以先畫成：

```text
Xiaomi C400
   │
   │ Xiaomi proprietary encrypted P2P
   │ (MISS / CS2)
   ▼
 go2rtc
   │
   ├── RTSP  ───► Python / OpenCV / PyAV
   │
   ├── WebRTC ──► Web application
   │
   ├── HLS ─────► Browser / player
   │
   └── stream ──► Frigate / AI / CV pipeline
                        │
                        ▼
                 YOLO / VLM / tracking
                 recording / detection
                 your own application
```

所以你的構想是可行的。

### 1. C400 本身不是一般的「開放 RTSP Camera」

我目前沒有找到 Xiaomi 對 C400 提供一個像：

```text
rtsp://192.168.1.50:554/live
```

這種官方公開 RTSP endpoint，也沒有看到 C400 官方宣稱支援 ONVIF。

它的架構比較像：

```text
C400
 │
 ├─ Mi Home / 米家
 │
 └─ Xiaomi encrypted P2P video
```

這也是為什麼你不能單純：

```python
cv2.VideoCapture("rtsp://camera-ip/...")
```

就取得影片。

更關鍵的是，小米自己維護的官方 Home Assistant `xiaomi_home` 專案明確說明：攝影機串流使用 **P2P encryption**，加密金鑰是在 Mi Home App 和攝影機之間協商；官方 Home Assistant integration 被視為 untrusted client，因此**不提供攝影機 live video stream**。:chatgpt-content-reference{index="1"}

所以這不是 Home Assistant 少做一個功能而已，而是 Xiaomi 的安全架構本身如此。

---

### 2. 但 C400 的確存在可以操作的 video interface

這裡事情就變得有趣了。

C400 的 MIoT specification 裡面實際存在：

```text
p2p-stream
```

以及：

```text
start-p2p-stream
stop-stream
camera-stream-for-google-home
stream-address
stream-auth-token
expiration-time
```

也就是說，攝影機內部本來就有一整套「建立串流 → 授權 → 取得串流 → 終止串流」的機制。:chatgpt-content-reference{index="2"}

問題只在於：

> Xiaomi 沒有把這套東西包裝成給一般使用者用的簡單公開 Camera API。

官方 Xiaomi IoT Developer Platform 比較偏向「硬體廠商把產品接進 Xiaomi 生態」，不是讓你買一台 C400 後，就拿一組 REST API key 自由取得 raw video。:chatgpt-content-reference{index="3"}

## 3. 現在最值得用的方法：go2rtc

這是我目前最推薦你的方案。

從 **go2rtc 1.9.13** 開始加入 Xiaomi Camera source，到了目前最新的 **v1.9.14（2026-01-19）**，又大幅改善了 Xiaomi 新款攝影機支援。:chatgpt-content-reference{index="4"}

而且它不是傳統的：

> 破解韌體 → root camera → 安裝 RTSP server

而是直接實作 Xiaomi Camera 使用的 P2P protocol。

go2rtc 官方文件說得很清楚：

> Xiaomi 2020 年之後逐漸採用統一的 `miss` camera protocol。

go2rtc 支援 `xiaomi/miss`、多種 `cs2` P2P transport，而且現在可以直接透過 Xiaomi 帳號登入，取得攝影機。:chatgpt-content-reference{index="5"}

最重要的是：

> 金鑰取得需要 Internet，但是實際 Camera → go2rtc 的影片連線可以走本地 LAN。

也就是：

```text
               Internet
                  │
             authentication
             / encryption key
                  │
                  ▼
C400 ─────────► go2rtc
      Local LAN
```

而不是：

```text
C400
 ↓
Xiaomi Cloud
 ↓
Internet
 ↓
your computer
```

go2rtc 官方文件明確寫：

> Each time you connect to the camera, Internet access is needed to obtain encryption keys.
>
> Connection to the camera is local only. :chatgpt-content-reference{index="6"}


對你這種要做 AI / CV / research prototype 的用途，這是很重要的差異。

# 5. 你實際上可以做到什麼？

如果跑：

```text
C400 → go2rtc
```

之後，你就可以把它當成普通的 IP Camera 使用。

例如 go2rtc 對外提供：

```text
rtsp://YOUR_SERVER:8554/c400
```

你的 Python 就可以：

```python
import cv2

url = "rtsp://127.0.0.1:8554/c400"

cap = cv2.VideoCapture(url, cv2.CAP_FFMPEG)

while True:
    ok, frame = cap.read()

    if not ok:
        break

    # your computer vision code
    print(frame.shape)

cap.release()
```

後面就完全進入你熟悉的 CV pipeline：

```text
C400

 ↓ live

go2rtc

 ↓ RTSP

FFmpeg / PyAV / OpenCV

 ↓ frames

YOLO
SAM
face detection
pose estimation
motion detection
VLM
OCR
tracking

 ↓

your application
```

例如：

```python
frame
   ↓
YOLO
   ↓
person detected?
   ↓
save frame
   ↓
SQLite / PostgreSQL
   ↓
notification
```

或者：

```text
C400
 ↓
live video
 ↓
local GPU
 ↓
VLM
 ↓
"What is happening in the room?"
 ↓
event database
```

這就完全可以。

## 我的結論

所以，如果你的問題是：

> 「在台灣買一台 Xiaomi C400，我能不能把即時影像拿出來，自己寫 Python/C++/Rust 程式做 computer vision、AI agent、錄影、偵測、VLM 等用途？」

答案是：

**可以，而且目前已經具有實際可行的開源方案。**

但正確理解是：

```text
❌ C400 原生公開 RTSP
❌ C400 原生 ONVIF
❌ Xiaomi 官方一般使用者 Camera REST API

✅ Xiaomi encrypted P2P stream
✅ go2rtc 解出 live stream
✅ local LAN video
✅ RTSP output
✅ WebRTC output
✅ H.265 video
✅ audio
✅ Python / FFmpeg / OpenCV / Frigate
```

最大的限制則是：

> **它仍依賴 Xiaomi 帳號以及取得 P2P encryption key 的流程，所以不是 100% vendor-independent、100% offline 的攝影機。** go2rtc 官方也明確指出，每次建立 Xiaomi camera connection 都需要網路取得 encryption keys。:chatgpt-content-reference{index="17"}

因此，如果你是「手上已經有 C400，想拿來研究」，我會直接用它；如果你是「專門為了建立長期可控的 Computer Vision / AI Agent Camera Lab 才準備買攝影機」，我反而會優先考慮**原生提供 RTSP + ONVIF 的攝影機**。那會少掉 Xiaomi authentication、P2P encryption、韌體 revision 和相容性這一整層風險。

以你現有的 Ubuntu + RTX 5080 環境，其實可以很自然地做成：

**C400 → go2rtc → RTSP → Python/PyAV → YOLO → event stream → local SLM/agent。**
可以，而且現在其實很適合做。若你的資料流是：

```text
Xiaomi C400
   ↓
go2rtc
   ↓
RTSP
   ↓
AI inference
```

那麼截至 **2026-10-01**，我會把可用的最新模型分成下面幾種，而不是把「影像辨識」全部當成同一類問題。

| 你想做什麼 | 我會先選 | 特點 |
|---|---|---|
| 人、車、狗、貓、包裹等即時偵測 | **YOLO26** | 快、成熟、最容易直接吃 RTSP |
| 不想事先限定類別，「找紅色背包」「找安全帽」 | **YOLOE-26** | Open-vocabulary detection + segmentation |
| 精準框出／分割／持續追蹤物體 | **SAM 3.1** | text prompt + segmentation + video tracking |
| 高準確率 detector、之後要 fine-tune | **RF-DETR** | 2026 很值得研究的 DETR 系列 |
| 理解「現在發生什麼事」 | **Qwen3-VL 4B/8B** | VLM，能做場景與事件語意理解 |
| 小型、頻繁地看 camera frame | **MiniCPM-V 4.6 1.3B** | 2026 新版，edge-oriented |
| 想要一個兼具 detection + caption + VQA 的模型 | **Moondream 3.1** | 很適合 camera application |
| 影像＋聲音一起理解 | **MiniCPM-o 4.5** | real-time streaming multimodal |

其中，我最推薦你先從 **YOLO26 + Qwen3-VL/MiniCPM-V 雙層架構**開始。

### 第一層：YOLO26，負責「一直看」

目前真正已經發布、可以直接拿來用的最新版 Ultralytics YOLO 是 **YOLO26**。YOLO27 已經在 2026 年 9 月 13 日 YOLO Vision 2026 公布，但截至現在仍是「coming later this year」，還沒有正式可用 checkpoint，所以現在不要把研究環境押在 YOLO27 上。:chatgpt-content-reference{index="0"}

YOLO26 本身可以做：

```text
Detection
Segmentation
Classification
Pose
Oriented bounding box
Semantic segmentation
Depth estimation
```

官方公布的 YOLO26 detection 五種尺寸在 COCO 上約為 40.9–57.5 mAP，而且設計重點就是 real-time / edge inference。:chatgpt-content-reference{index="1"}

更方便的是，Ultralytics **原生就接受 RTSP stream**。所以甚至不必自己先寫 OpenCV decoder：:chatgpt-content-reference{index="2"}

```python
from ultralytics import YOLO

model = YOLO("yolo26s.pt")

stream = "rtsp://127.0.0.1:8554/c400"

for result in model.predict(
    source=stream,
    stream=True,
    device=0,
    imgsz=640,
):
    print(result.boxes)
```

你的架構就直接變成：

```text
C400
 ↓
go2rtc
 ↓
rtsp://localhost:8554/c400
 ↓
YOLO26
 ↓
person / car / dog / cat / ...
 ↓
event
```

所以如果你的第一個 POC 是：

> 有沒有人進來？
> 有沒有狗？
> 桌上有沒有東西？
> 車子經過幾次？

我會直接用 **YOLO26s** 起跑，而不是 VLM。

### 第二個很值得玩的：YOLOE-26

如果你開始覺得：

> 「COCO 的固定 80 類太侷限了。」

那 YOLOE-26 會非常有趣。

它是 **open-vocabulary detector**，可以直接在 runtime 告訴它：

```python
model.set_classes([
    "person",
    "red backpack",
    "coffee cup",
    "motorcycle helmet",
])
```

而不一定要先為每個類別重新標資料、重新訓練。

YOLOE-26 支援：

```text
文字 prompt
視覺 exemplar
prompt-free vocabulary
bounding box
instance segmentation
```

官方甚至內建 4,585 個名稱的 prompt-free vocabulary。:chatgpt-content-reference{index="3"}

這對 surveillance / smart-home 類應用很重要。

傳統 YOLO：

```text
我訓練過：
person
car
dog

→ 只能很好地找這些
```

YOLOE：

```text
今天：
"yellow umbrella"

明天：
"delivery package"

後天：
"person wearing helmet"
```

不一定每次都重新 train。

對你的研究性質，我反而認為 **YOLOE-26 比純 YOLO26 更值得玩**。

### 第三個：SAM 3.1，負責「這個東西到底在哪裡？」

Meta 在 2025 年推出 SAM 3，而 **SAM 3.1 是 2026-03-27 的更新版**。

現在它已經不只是早期 SAM 那種：

> 點一下 → 把這個物體切出來。

而是可以：

```text
文字 prompt
     ↓
"person wearing a red shirt"

     ↓
detect

     ↓
segment

     ↓
track through video
```

SAM 3 可以用文字或 visual exemplar 找出並追蹤概念；SAM 3.1 又加入 object multiplexing，一次 forward 可以追蹤最多 16 個 objects。Meta 報告中，在單張 H100、medium number of objects 的條件下吞吐可從 16 提升到約 32 FPS。:chatgpt-content-reference{index="4"}

但注意：

**我不建議你拿 SAM 3.1 對 C400 30 FPS 每一幀都硬跑。**

它更適合：

```text
YOLO26
 ↓
有人出現
 ↓
SAM 3.1
 ↓
精準 segment + track
```

而不是：

```text
C400 30 FPS
 ↓
SAM 3.1
 ↓
每一幀全畫面分析
```

這是兩種完全不同的 compute budget。

### 第四個：RF-DETR

如果你之後想把這變成一個正式 Computer Vision research project，我會把 **RF-DETR** 加進 benchmark。

RF-DETR 已被列為 **ICLR 2026** 模型，而且提供 detection / segmentation，尤其強調 fine-tuning。Roboflow 自己公布的 benchmark 中，例如 RF-DETR-M 是 COCO AP 54.7、約 4.52 ms latency；不過這是開發者自己的 benchmark，應視為候選比較數據，而不是第三方最終裁決。:chatgpt-content-reference{index="5"}

而且它有一個對你未來產品化可能很實際的點：

```text
RF-DETR → Apache 2.0
YOLO26 → AGPL-3.0 / commercial license
```

因此如果未來不是研究，而是要包成 closed-source application，license 會變成真正的架構變數。:chatgpt-content-reference{index="6"}

## 但真正有趣的是 VLM

```text

chair
dog
cup

```

可是你大概很快就會想要：

這就不是普通 object detection。

例如畫面：

```text
┌─────────────────────────┐
```

VLM 則可能回答：

### Qwen3-VL

目前 Qwen3-VL 是非常強的本地 VLM 選項。

```text

4B
8B
32B
30B-A3B
235B-A22B
...
```

Qwen 官方在 2025 年 10 月釋出了 4B、8B 等 dense models。Qwen3-VL 特別強調 spatial perception、video dynamics、video temporal understanding，以及 timestamp-grounded event localization。:chatgpt-content-reference{index="7"}

例如你可以每 2 秒抽一張：

```text

 ↓
go2rtc
```


這就是 YOLO 做不到的事情。

以你這台 RTX 5080 16GB，我會優先實驗 **Qwen3-VL-4B-Instruct**；8B 可以再視量化、context 和 video token 數量調整。

## MiniCPM-V 4.6 更有意思

如果你的重點是：

> 「我要讓 camera 長時間、頻繁地送 frame 給 VLM。」

我會認真測 **MiniCPM-V 4.6**。

它在 **2026-05-11** 開源，只有約 **1.3B**，而且團隊就是針對 edge deployment 與 image/video understanding 設計；官方也特別強調視覺 token compression。:chatgpt-content-reference{index="9"}

因此：

```text
Qwen3-VL
→ reasoning 強
→ 比較像「視覺大腦」
```

# 如果是我要幫你建，我會這樣做

不是：

```text
C400
 ↓
一個超強 VLM
 ↓
全部交給它
```

而是：

```text
                   Xiaomi C400
                        │
                      H.265
                        │
                     go2rtc
                        │
                      RTSP
                        ↓
              ┌──────────────────┐
              │   Frame Router   │
              └────────┬─────────┘
                       │
         ┌─────────────┴──────────────┐
         │                            │
         ▼                            ▼
     YOLO26s                     Audio / frames
    10~30 FPS                       sampled
         │                            │
         ▼                            ▼
 person / car                 MiniCPM-V / Qwen3-VL
 dog / package                       │
 pose / object                       │
         │                            │
         └───────────┬────────────────┘
                     ↓
                Event Engine
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
      JSON        Database      Agent
        │
        ↓
{
  "time": "...",
  "event": "person_entered",
  "objects": ["person", "package"],
  "description":
     "A person entered carrying a box."
}
```

關鍵概念是：

**Detector 負責 perception；VLM 負責 interpretation。**

不要讓 VLM 每秒看 30 張圖。通常比較有效率的是：

```text
YOLO26
30 FPS
↓
發現值得注意的 event
↓
保留 event 前後 3～10 秒
↓
抽 4～16 frames
↓
Qwen3-VL / MiniCPM-V
↓
semantic interpretation
```

如此 GPU 使用量會低非常多，而且 VLM 得到的是「有意義的事件」，不是幾萬張幾乎一模一樣的畫面。
